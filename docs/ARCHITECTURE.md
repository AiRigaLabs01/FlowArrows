# FlowArrows — Architecture

## Главный принцип

Игровая логика отделяется от визуального слоя Godot. Solver и generator не должны зависеть от Node2D, Control, анимаций или Android API. Это позволит тестировать математическое ядро отдельно от UI.

## Модули

```text
FlowArrows
├── core
│   ├── board
│   ├── piece
│   ├── move
│   └── geometry
├── solver
├── generator
├── difficulty
├── validation
├── game
├── ui
└── persistence
```

## Core

Core содержит детерминированную модель поля. Для одного BoardState должны однозначно вычисляться доступные ходы.

## Solver

Solver получает BoardState и возвращает:

- solvable;
- найденное решение;
- число исследованных состояний;
- статистику ветвления;
- при необходимости несколько альтернативных решений.

Для MVP допустим DFS/backtracking с memoization. Позже можно добавить более эффективный поиск.

## Generator

Generator работает в несколько стадий:

1. выбирает параметры сложности;
2. создаёт логическую структуру решения;
3. размещает pieces;
4. формирует блокировки;
5. запускает validator;
6. запускает solver;
7. вычисляет difficulty score;
8. принимает или отбрасывает уровень.

## Validator

Проверяет как минимум:

- отсутствие некорректных пересечений;
- валидность траекторий;
- наличие хотя бы одного начального хода;
- достижимость полного очищения поля;
- соответствие решения фактической геометрии.

## Game layer

GameSession управляет состоянием текущей партии, history для Undo, подсказками и завершением уровня.

## UI

UI только отображает состояние GameSession и отправляет намерения игрока. Визуальный объект PieceView не является источником истины для логики.

## Persistence

Локально сохраняются настройки, прогресс, статистика и при необходимости seed процедурного уровня.

## Детерминизм

Процедурные уровни должны воспроизводиться по seed. Это позволит повторять ошибки генератора и в будущем реализовать daily puzzle без хранения полной геометрии каждого уровня.
